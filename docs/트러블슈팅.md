제목 : [regulation_chunk 벌크 적재/N+1 성능 문제] 프로젝트 - 1
1. 문제 개요
오류 상황: 벌크 적재 API가 각 청크마다 DB 중복 조회와 OpenAI 임베딩 호출을 개별 수행해 요청 수가 늘수록 성능이 급격히 저하되는 구조였습니다.
발생 배경: 코드 리뷰에서 20건 벌크 적재 시 DB 쿼리와 외부 API 호출이 각각 20번씩 발생하는 N+1 문제가 지적되었습니다.
2. 오류 코드 및 오류 메시지
오류 코드: 명시적인 HTTP 오류는 아니지만, 응답 지연과 외부 API 호출 수 증가가 문제였습니다.
오류 메시지: 별도 메시지 없음
관련 로그: 벌크 생성 로직에서 `find_by_chunk_id()`와 `create_embedding()`이 반복 호출되는 구조가 확인되었습니다.
3. 원인 분석
오류 원인: 벌크 적재 로직이 단건 생성 내부 함수를 그대로 반복 호출하면서 DB 조회와 임베딩 생성을 배치 처리하지 못했습니다.
에러 로그 해석: 직접적인 에러 로그보다 서비스 코드 구조를 분석했을 때 N+1 패턴이 명확히 드러났습니다.
구조적 이해: OpenAI Embeddings API는 문자열 배열 입력을 지원하고, SQLAlchemy도 `IN` 쿼리로 여러 키를 한 번에 조회할 수 있어 벌크 적재 최적화가 가능합니다.
4. 해결책
단계별 조치 방법:
Step 1: repository에 `find_existing_chunk_ids()`를 추가해 chunk_id 중복 여부를 한 번의 쿼리로 조회했습니다.
Step 2: embedding service에 `create_embeddings_batch()`를 추가해 여러 chunk_text를 한 번의 OpenAI 호출로 처리했습니다.
Step 3: bulk service가 중복 체크, chunk_text 생성, 배치 임베딩 생성, DB 저장을 각각 한 번씩만 수행하도록 리팩터링했습니다.
코드 예시:
```python
existing_chunk_ids = find_existing_chunk_ids(db, chunk_ids)
embeddings = create_embeddings_batch(chunk_texts)
```
추가 자료: https://platform.openai.com/docs/api-reference/embeddings/create
5. 교훈 및 주의 사항
주의할 점: 단건 생성 함수를 단순 반복 호출하면 bulk 처리에서 쉽게 N+1 문제가 생깁니다.
배운 점: bulk API는 처음부터 배치 DB 조회와 배치 외부 호출 구조를 염두에 두고 설계해야 성능 문제를 예방할 수 있습니다.
